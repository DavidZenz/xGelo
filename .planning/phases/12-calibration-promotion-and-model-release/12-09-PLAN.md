<objective>
Close the PROMO-03 verification gap by making the exported World Cup dashboard builders exclusively consume one validated Phase 12 approved or incumbent-retained release, while preserving the current dashboard presentation and forecast behavior for a valid release.

Purpose: D-15 requires manifest-and-contract-only model loading and D-16 requires an incumbent-retained release to remain usable. The inspected validator currently reads model/calibrator RDS files inside complete-bundle validation, so the consumer boundary needs a metadata-only preflight seam before the full resolver. The public builders must also reject raw model paths and baseline-selection arguments before any resolver or forecast setup.

Output: A strict release-only dashboard/export API, a reusable metadata-only release preflight with a pinned manifest candidate, preserved default publisher/installer validation behavior, and regression coverage for valid, missing, ambiguous, unapproved, invalid, hash-mismatched, wrong-candidate, wrong-G, and forged-identity release states.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Caller input -> dashboard boundary | release_root, optional approved-release identity, variadic model/baseline arguments, and manifest-path controls are untrusted inputs. |
| Trusted root -> metadata preflight | Candidate discovery, safe-relative paths, manifest, contract, complete artifact set, labels, and hashes are checked without loading model objects. |
| Validated release -> full resolver/model loader/forecast engine | Only the preflight-pinned and identity-matched release may cross into RDS loading and forecasting. |
| Forecast payload -> dashboard/export presentation | Release metadata and forecast rows cross into JSON, CSV, HTML, and client-side rendering; WC2026 labels must remain outside this boundary. |
