<objective>
Close the PROMO-03 verification gap by making the exported World Cup dashboard builders exclusively consume one validated Phase 12 approved or incumbent-retained release, while preserving the current dashboard presentation and forecast behavior for a valid release.

Purpose: D-15 requires manifest-and-contract-only model loading and D-16 requires an incumbent-retained release to remain usable. The inspected validator currently reads model/calibrator RDS files inside complete-bundle validation, so the consumer boundary needs a metadata-only preflight seam before the full resolver. The preflight must also treat the bundled freeze/final-evaluation evidence plus benchmark-report decision identity as candidate authority, keep the external promotion-report file hash as separate audit provenance, treat contract-declared artifact paths as authoritative under the accepted two-model-row role convention, and reject ambiguous root/child manifest topology. The public builders must also reject raw model paths and baseline-selection arguments before any resolver or forecast setup.

Output: A strict release-only dashboard/export API, a reusable metadata-only release preflight with an authoritative candidate decision and pinned manifest candidate, contract-path-driven model loading, preserved default publisher/installer validation behavior, and regression coverage for valid, missing, ambiguous-topology, unapproved, invalid, role/path-mismatched, independently hash-mismatched, unsafe/missing artifact metadata, wrong-candidate, wrong-G, and forged-identity release states.
</objective>
