<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Final decision/artifacts → release staging | A partial or tampered decision bundle could become consumer-visible. |
| Release manifest/contract → model loader | Manifest paths, hashes, statuses, and identities control which model is loaded. |
| Release resolver → dashboard/export HTML/JSON/CSV | Presentation must not emit forecasts before validation or expose holdout labels. |
| Targets DAG → durable outputs | Incorrect ancestry could make label-bearing data available to calibration or freeze targets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-12-05-01 | Tampering | Model/calibrator/contract/release hashes | critical | mitigate | Hash every required artifact, validate from a fresh process, require exact status/identity/G=40, and reject any mismatch before `readRDS()` or forecast generation. |
| T-12-05-02 | Spoofing | Trusted release root and manifest paths | high | mitigate | Normalize every path under the configured trusted root; reject absolute, escaping, ambiguous, stale, and mtime/latest-based resolution. |
| T-12-05-03 | Denial of service | Staged release installation | high | mitigate | Use unique sibling staging, pre/post validation, atomic rename, retained backup, and rollback on post-install failure. |
| T-12-05-04 | Information disclosure | Dashboard/export payloads | high | mitigate | Keep WC2026 labels outside consumer-facing artifacts and assert absence from JSON/CSV/HTML; expose only approved release metadata. |
| T-12-05-05 | Elevation of privilege | Dashboard target and raw model paths | critical | mitigate | Remove production path/existence authority and require `resolve_phase12_approved_release()` for every view/export. |
| T-12-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation is planned; any attempted install requires the package legitimacy gate and blocking human verification. |
</threat_model>
