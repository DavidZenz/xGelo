<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Final decision → staged bundle | Partial or tampered decision evidence must not become consumer-visible. |
| Release files → manifest hashes | Paths, status, identities, and hashes control bundle integrity. |
| Stage → accepted release root | Atomic replacement must not discard the known-good bundle on validation failure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-12-06-01 | Tampering | Model/calibrator/manifest/report hashes | critical | mitigate | Hash every required artifact, validate status/identity/G=40, and reject any mismatch before installation. |
| T-12-06-02 | Spoofing | Trusted release paths | high | mitigate | Persist only trusted-root-relative paths and reject absolute/escaping/ambiguous artifacts. |
| T-12-06-03 | Denial of service | Atomic installation | high | mitigate | Use unique staging, pre/post validation, retained backup, atomic rename, and rollback. |
| T-12-06-04 | Information disclosure | Consumer-facing reports and models | high | mitigate | Reject WC2026 label content outside the scoring/reporting boundary and assert absence from release files. |
| T-12-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation is planned; any attempted install requires legitimacy review and blocking human verification. |
</threat_model>
