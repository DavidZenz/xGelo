# Phase 20: UCL Rules, State, and Tournament Outcomes - Context

**Gathered:** 2026-09-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Build the rules-correct UEFA Champions League competition layer from the accepted 36-club league-phase state through the final. This phase owns the editioned league table and tie-break trace, accepted eight-opponent schedules, immutable pre-kickoff forecast ledger, conditional league-phase and knockout simulation, stage reconciliation, and byte-replayable outcome artifacts.

It does not own dashboard rendering or N-edition atomic publication (Phase 21), scheduled refresh and operational hardening (Phase 22), source/provider acceptance (Phase 18), or club-model training and promotion (Phase 19).

</domain>

<decisions>
## Implementation Decisions

### Rules authority and tie resolution
- **D-01:** Recompute the league-phase table from accepted match state using one editioned, manually reviewed UEFA rules contract. Provider standings remain reconciliation evidence and cannot replace the project-owned ranking computation. — **Reversibility:** costly — published rank and qualification artifacts depend on the ruleset identity and trace schema.
- **D-02:** Apply every available tie-break criterion in official order and emit an auditable criterion/subset trace. If required late-criterion evidence is unavailable, stop at the last provable criterion, preserve a shared unresolved rank interval, and suppress any downstream path that requires an exact rank.
- **D-03:** Qualification bands are derived from the recomputed table: ranks 1–8 advance directly, 9–24 enter the knockout play-offs, and 25–36 are eliminated. No provider-supplied band or rank silently overrides the rules adapter.

### League schedule and forecast ledger
- **D-04:** Accept the league-phase schedule only when all 36 clubs and exactly 144 fixtures validate with stable club and fixture identities, eight distinct opponents per club, matchday, home/away side, kickoff, lifecycle, score semantics, and source lineage. Never infer missing pairings.
- **D-05:** A fixture forecast is durable evidence only when generated by the selector-authorized club release before kickoff with a strict exclusive cutoff. Completed fixtures retain that immutable pre-kickoff forecast; they are never regenerated after the result is known.
- **D-06:** Retain one typed ledger row for every fixture. Ineligible or blocked forecasts carry an explicit reason such as release unavailable, kickoff unconfirmed, identity unresolved, insufficient model evidence, or cutoff violation; absent forecasts are not silently omitted.

### League-phase probability outputs
- **D-07:** Condition simulations on accepted completed results and simulate only eligible remaining fixtures. Settled matches are fixed and are never resampled.
- **D-08:** Publish mutually exclusive top-8, ranks 9–24 play-off, and ranks 25–36 eliminated probabilities for every club, together with the full rank distribution and documented rank-8/rank-24 cut-line distributions.
- **D-09:** If an unresolved tie can change a qualification band and no official criterion can resolve it, the affected probability output remains explicitly unresolved instead of using lexical, source-order, or random fallback ranking.

### Knockout path conditioning and match resolution
- **D-10:** Before an official draw is accepted, enumerate or sample only paths allowed by the editioned rank-constrained draw rules. Once a validated draw artifact exists, condition on it exactly. Never assume a fixed bracket or pair teams uniformly across illegal paths. — **Reversibility:** costly — draw-path identities flow into every downstream stage probability and published lineage.
- **D-11:** Resolve two-leg ties by aggregate goals under the editioned leg-order policy, with no away-goals rule. If level after leg two, apply required extra time and penalties at the second-leg venue. The final is one match at a neutral venue with its official extra-time/penalty policy.
- **D-12:** Completed draw and knockout evidence is authoritative only when it belongs to the same accepted edition/source lineage. Missing, stale, partial, or contradictory draw artifacts produce an explicit unresolved path state.

### Reproducibility and fail-closed artifacts
- **D-13:** Bind the accepted source bundle, ruleset, club release, accepted draw artifacts, information cutoff, simulation algorithm/version, simulation count, and seed into the projection-run identity and canonical artifact hashes. — **Reversibility:** one-way — changing this published identity contract requires a versioned artifact migration and validator compatibility path.
- **D-14:** Identical accepted inputs and seed must reproduce byte-equivalent canonical outcome artifacts; generation timestamps or filesystem order must not affect identities or row order.
- **D-15:** Per-club probabilities must reconcile with prerequisite league bands, remain monotone from play-off through champion, sum exactly across mutually exclusive outcomes, and be validated before any artifact is accepted. Dashboard-side normalization is forbidden.
- **D-16:** Missing production authority publishes only typed blocked or unresolved diagnostic state. Fixture-mode evidence remains non-promotable, cannot create a production selector, and cannot overwrite accepted incumbent bytes.

### Claude's Discretion
- Choose exact R module boundaries, table names, compact file paths, stable row ordering, and reason enums while preserving the existing canonical-v2 and edition-scoped contracts.
- Choose deterministic enumeration versus seeded sampling for legal future draw paths based on bounded runtime and exactness, but document the choice and validate path legality.
- Choose focused fixture sizes for tests, while production schemas and cardinality checks retain the complete 36-club/144-fixture contract.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `R/competition/match_state.R` already supplies the score and lifecycle contract needed for league and knockout fixtures.
- `R/competition/standings.R` provides universal played/win/draw/loss/goals/points computation, leaving Phase 20 to add the UCL-specific ordered rules adapter and trace.
- Phase 15 and 16 rules/simulation/outcome modules already demonstrate editioned rulesets, explicit unresolved evidence, deterministic seeded paths, two-leg resolution, stage ledgers, reconciliation, and immutable bundles.
- `R/club/release.R` now exposes the typed club-only resolver and rejects fixture evidence at production boundaries.
- Phase 18's UCL source bundle already distinguishes accepted current state from blocked, fixture, or incomplete evidence.

### Established Patterns
- Durable contracts are file-backed CSV/JSON/RDS artifacts with stable IDs, canonical-v2 hashes, exact schemas, explicit cutoffs, and source/model/rules lineage.
- Production paths fail closed; fixture paths prove mechanics but cannot promote or mutate selectors.
- Simulation randomness is explicit and deterministic, and accepted artifacts use stable row ordering independent of timestamps and filesystem enumeration.
- Missing rules, draws, identities, or forecasts remain typed unavailable or unresolved rather than guessed.

### Integration Points
- New UCL rules/state/simulation modules should compose from `R/competition/` and consume only the Phase 18 accepted UCL bundle plus the Phase 19 production club resolver.
- `_targets.R` and a Phase 20 command wrapper will orchestrate validation, projection, and outcome-bundle generation without giving callers selectable production evidence roots.
- Phase 20 output schemas become the sole competition-outcome input to the Phase 21 shared dashboard and N-edition publisher.

</code_context>

<specifics>
## Specific Ideas

- The user wants a Champions League dashboard analogous to the existing competition dashboards, but Phase 20 deliberately establishes trustworthy competition truth before any UI work.
- League-phase ranking must visibly explain the decisive criterion or show an unresolved tied interval; a superficially complete but guessed table is unacceptable.
- Completed fixtures should keep their original pre-kickoff forecast so later accuracy and dashboard history remain auditable.

</specifics>

<deferred>
## Deferred Ideas

- Shared UCL dashboard pages, responsive charts, filters, and atomic N-edition publication belong to Phase 21.
- Scheduled acquisition, retries, non-overlap, failure injection, performance, browser/accessibility acceptance, and end-to-end refresh belong to Phase 22.
- User-authored what-if scenarios and richer forecast-change explanations remain v4.x future work.

</deferred>
