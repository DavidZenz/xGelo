<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| activation/rules/simulation inputs -> outcomes builder | Upstream state, rule, topology, and probability tables must be schema and lineage valid before aggregation. |
| candidate outcomes -> accepted output directory | Candidate files must be validated and hashed before atomic replacement. |
| CLI arguments/filesystem -> builder | Paths and flags are untrusted and must be constrained to the declared input/output contract. |
| outcomes bundle -> later UI consumer | Status, warnings, empty collections, stable IDs, and lineage must be truthful and renderer-neutral. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-16 | Tampering | `phase16_write_euro_outcomes_bundle()` | critical | mitigate | Validate exact inventory, schemas, IDs, lineage, canonical hashes, and candidate status before atomic replacement. |
| T-16-17 | Tampering | source/rules/model/cutoff lineage | high | mitigate | Include and verify each revision/hash in manifest and replay comparison; reject mismatches. |
| T-16-18 | Denial of Service | CLI input/output paths | medium | mitigate | Constrain accepted paths/flags and validate bounded CSV inputs before building or writing. |
| T-16-19 | Information Disclosure | pre-draw or rejected candidate output | high | mitigate | Publish control metadata only and keep candidate/blocked projection rows out of the accepted bundle. |
| T-16-20 | Repudiation | manifest and replay | medium | mitigate | Record deterministic hashes, seed/count, build timestamp/refresh, accepted/candidate revision IDs, and reason codes. |
| T-16-21 | Spoofing | plan-owned CLI/wrapper | medium | mitigate | Keep the UEFA wrapper thin and delegate to the same validated builder; bind edition/source identity before writing. |
</threat_model>
