<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| official source bundle -> activation validator | Source metadata, resource rows, IDs, hashes, and timestamps are untrusted until schema and identity checks pass. |
| candidate revision -> accepted state | A correction must not alter the last accepted active bundle while validation is incomplete. |
| activation envelope -> forecast consumers | Downstream code must receive explicit status and empty collections when prerequisites are absent. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-01 | Tampering | `phase16_validate_euro_source_bundle()` | high | mitigate | Validate edition/source/rules identities, required resources, stable IDs, completeness, and canonical hashes before returning active. |
| T-16-02 | Spoofing | source confidence and accepted-bundle metadata | high | mitigate | Bind activation to the known Phase14 source-bundle identity and explicit official-source metadata; reject unknown identities. |
| T-16-03 | Denial of Service | incomplete or malformed candidate revision | medium | mitigate | Return a bounded structured unavailable/revision-blocked result and retain the last accepted reference without traversing unbounded content. |
| T-16-04 | Information Disclosure | candidate rows in activation payload | medium | mitigate | Keep candidate content isolated and publish only accepted rows; invalid and pre-draw collections remain empty. |
| T-16-05 | Repudiation | source/rules revision transition | medium | mitigate | Emit deterministic revision IDs, hashes, reason codes, and warning metadata in the activation envelope. |
</threat_model>
