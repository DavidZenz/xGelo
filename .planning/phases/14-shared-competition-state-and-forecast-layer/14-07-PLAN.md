## Atomic inventory rationale

The thirteen release files are one immutable manifest/hash/semantic envelope: the manifest authenticates every object, contract, report, and provenance parent, while the contract cross-checks model, calibrator, gate, cutoffs, and unchanged score-distribution identity. Splitting installation would expose a durable release ID with a partial or unverifiable inventory, so candidate validation and the single atomic directory rename must remain one plan; the separately listed test file is the non-durable proof surface.
