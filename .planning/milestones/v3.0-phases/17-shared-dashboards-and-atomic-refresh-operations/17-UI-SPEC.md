# Phase 17 - UI Design Contract

> Visual and interaction contract for the shared Nations League and EURO qualifying dashboards. Generated by gsd-ui-researcher.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none; extend the existing static R-generated HTML/JavaScript renderer |
| Icon library | none; use text labels, borders, and existing status marks so state is never color-only |
| Font | Arial, Helvetica, sans-serif |

The two routes must be dedicated entry points rendered by the same renderer and neutral payload schema. Edition differences belong in adapters and typed data, not duplicated markup or edition-specific rendering branches. Preserve the World Cup and Phase 16 visual language: `#f7f6f2` paper background, white panels, thin `#d8d8d8` rules, compact tables, blue top rules for primary metrics, native `<details>` disclosures, and text-first state labels.

## Spacing Scale

Declared values are multiples of 4:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline metadata, status-mark gaps, table micro-padding |
| sm | 8px | Filter gaps, warning contents, chips, disclosure contents |
| md | 16px | Panel padding, toolbar spacing, section spacing |
| lg | 24px | Page header, state summary, major section padding |
| xl | 32px | Gaps between dashboard zones |
| 2xl | 48px | Major page-level breaks |
| 3xl | 64px | Page-level spacing only |

Exceptions: interactive controls and disclosure summaries must have at least 44px total hit height on touch layouts. Keep stable table geometry; do not introduce intermediate spacing values to solve overflow.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 700 | 1.2 |
| Heading | 20px | 700 | 1.2 |
| Display | 30px | 700 | 1.1 |

Use tabular numerals for ranks, points, goals, dates, counts, probabilities, seeds, and timestamps. Use the compact 12px label treatment for source confidence, status reasons, hashes, ruleset versions, and model lineage. Long IDs, URLs, and warning text must wrap inside bounded disclosures; never widen the page or overlap adjacent content.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f7f6f2` | Page background and whitespace |
| Secondary (30%) | `#ffffff` | Header, summary, filters, tables, disclosures, and content panels |
| Accent (10%) | `#3573a8` | Active route/section/filter, primary rules, available-state emphasis, forecast bars, and selected rows |
| Destructive | `#b23a2f` | Blocked refresh, invalid candidate, or failed publication warning only |

Accent is reserved for active navigation and filters, primary section rules, available/accepted state emphasis, selected team or row, forecast probability bars, and links that open rules or lineage. Do not tint every control blue. Existing semantic colors remain allowed: `#d29d2b` for warning/revision attention and `#3b8754` for positive/resolved outcomes. Every color-coded state must also include a text label or symbol.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `View projected outcomes` |
| Empty state heading | `No accepted data for this section` |
| Empty state body | `This section is intentionally unavailable in the current competition state. The accepted source bundle does not contain the required structure or evidence, so no groups, fixtures, standings, or probabilities are fabricated.` |
| Error state | `Refresh blocked - showing the last accepted snapshot. The candidate bundle failed validation; inspect refresh details for the reason.` |
| Destructive confirmation | `None - refresh and publication are backend operations. The dashboard never asks the user to delete, replace, or confirm data.` |

Required state labels: `Available`, `Pre-draw`, `Refresh pending`, `Refresh blocked`, `Unavailable`, `Unresolved`, `Suppressed`, and `Showing last accepted snapshot`. Never represent unavailable probabilities as `0%`.

## Phase Surface Contract

### Entry points and shared shell

Publish two dedicated routes with stable titles and route identity:

- `/competitions/nations-league/` - `UEFA Nations League 2026/27 Forecast`
- `/competitions/euro-qualifying/` - `EURO 2028 Qualifying Forecast`

The header must show the edition name as the primary title, a short state label, and a compact route switcher linking to the other competition. The route switcher is navigation, not a data filter; it must not imply that changing routes shares state or forecasts. Below the header, render the same shell in this order: state summary, warning strip when needed, section navigation, filter toolbar, primary sections, and collapsed credits/lineage disclosures.

The shell must work at desktop and mobile widths. At desktop, use a constrained content width with two-column layouts only where tables remain readable. At mobile, collapse to one column, allow section navigation and filters to wrap, and preserve the same order and labels. Do not use a marketing hero, decorative gradients, or dashboard cards nested inside cards.

### State summary and refresh continuity

Render a compact state summary before competition data. It must show, in order:

1. Lifecycle state: `pre_draw`, `scheduled`, `in_progress`, or `complete`, translated to a human label.
2. Forecast state: `available`, `pre_draw`, `unavailable`, `blocked`, or `suppressed`.
3. Last accepted refresh time and `batch_id`.
4. Source confidence and source mode: official or reviewed fallback.
5. Model release and model-data cutoff when forecast data exists.
6. A warning summary when the current or candidate refresh is pending/blocked.

`last_refresh_at_utc` is source/refresh freshness; `generated_at_utc` is page generation time. Show both in lineage, never conflate them. When a candidate refresh is running or fails, retain the last accepted content and show `Refresh pending` or `Refresh blocked` plus `Showing last accepted snapshot`. Candidate rows, hashes, or unaccepted forecasts must never appear in the public sections.

Atomic publication is invisible as an implementation detail but visible as coherent metadata: both routes in a published batch must carry the same `batch_id`, publication timestamp, and batch status. The dashboard must never expose a mixed revision.

### Section navigation

Use a compact tab or anchor navigation with these labels:

`Overview`, `Structure`, `Standings`, `Fixtures`, `Results`, `Form`, `Match forecasts`, and `Projected outcomes`.

The active section uses the ink/blue active treatment already present in the World Cup dashboard. Section navigation is keyboard reachable, has a visible focus state, and preserves the warning strip above it. A section with an unavailable collection remains in navigation and opens its explicit unavailable surface; it is not silently hidden.

### Filter contract

The toolbar appears immediately below section navigation and filters the current shared payload client-side. It must expose these dimensions whenever their option set exists:

| Dimension | Control | Values and behavior |
|-----------|---------|---------------------|
| Section | Tab/anchor navigation | One active section; does not remove the warning or change accepted data |
| League/group | `<select>` or compact segmented control | `All`, then only accepted league/group IDs for the current edition; use `League A-D` for Nations League and official group labels after EURO activation |
| Team | Searchable/select control | `All teams` plus stable display names; matching filters both home and away rows and standings/form rows |
| Matchday | `<select>` | `All matchdays` plus accepted matchday values in ascending order |
| Fixture status | `<select>` | `All`, `Scheduled`, `In progress`, `Final`, `Postponed`, `Unavailable`; preserve explicit source status |

On desktop, place controls in one wrapping toolbar with labels above or beside each control. On mobile, stack controls full width in the same order. Every filter has a visible `Clear filters` text action when non-default values are active. Filtering must update result counts and empty copy without mutating the payload, hiding warnings, or changing metadata. A no-match filter result is distinct from an unavailable data section and uses `No rows match the selected filters.`

### Overview

The overview is the default section and contains only accepted, high-signal facts: edition status, next relevant fixtures or recent results, compact standings/forecast highlights, and a projected-outcomes entry point. Keep operational metadata secondary in a quiet summary row or disclosure. Do not place a large refresh console above the football content.

### Structure and standings

Structure must render the accepted competition topology using edition-neutral section names with edition-specific labels supplied by the payload. Nations League must distinguish Leagues A-D, groups, knockout stage, and applicable promotion/relegation paths. EURO must show official groups and qualifying/play-off structure only after an accepted post-draw bundle exists.

Standings tables must expose stable rank, team, played, wins/draws/losses, goals for/against or goal difference where accepted, points, and a status/rule note where applicable. Preserve group/league identity in the table heading and filter context. Use horizontal scrolling for dense tables on narrow viewports, stable column widths, sticky team identity only if it does not obscure the row, and no probability heatmap for unavailable values.

### Fixtures, results, form, and match forecasts

Fixtures and results share a compact match-row pattern: matchday/date, stage or group, home team, away team, venue or kickoff where available, and explicit status. Final results show scores; scheduled fixtures show kickoff and do not display fabricated scores. Preserve postponed, unresolved, and unavailable statuses as text.

Form is a separate evidence surface. Label competition form, all-international form, and national-team xG evidence independently when present. An unavailable xG source must read `Unavailable - no accepted national-team xG source` rather than borrowing club or result history.

Match forecasts show calibrated 1X2 probabilities only for eligible fixtures. Use a compact three-part bar or table with `Home`, `Draw`, and `Away` labels, percentage values, model release, feature cutoff, and an explicit `Forecast unavailable` reason when suppressed. Forecast bars are explanatory, not interactive controls. Per-match simulation detail may be disclosed but must not imply live odds or betting advice.

### Projected outcomes

Make projected outcomes a status-bearing section, not an opaque headline probability. Nations League must accommodate projected standings, League A quarter-final/title paths, direct promotion/relegation, and applicable play-offs. EURO must accommodate direct qualification, host-reserved places, Nations League-linked play-off eligibility, and each valid topology. Keep the edition-specific labels in the payload; the renderer uses shared rows, badges, and disclosures.

Every projected row may show team, stage/outcome, probability when available, status, reason, and lineage reference. Use `Unavailable`, `Suppressed`, or `Unresolved` in the value cell when evidence is absent. Do not render fabricated brackets, group assignments, teams, or probabilities for EURO `pre_draw`, unresolved, insufficient-source, or unsupported-topology states.

### Unavailable, pre-draw, partial, and blocked sections

Every section has a typed status: `available`, `pre_draw`, `unavailable`, `unresolved`, `suppressed`, or `blocked`, plus a human-readable reason. Preserve the section heading and its normal position so activation does not rearrange the page. Render a bounded status panel with the copy from the Copywriting Contract and a `Why unavailable` native disclosure containing the exact reason and required source/evidence.

For EURO `pre_draw`, show the edition-level pre-draw banner and empty-but-schema-valid Structure, Standings, Fixtures, Results, Form, Match forecasts, and Projected outcomes sections. Show no guessed groups, fixtures, standings, teams, bracket slots, or probabilities. For an active bundle with zero completed results, show real groups and fixtures, plus `No completed results yet` for Results; do not mark the whole edition unavailable.

For partial data, render available sections normally and unavailable sections explicitly. For blocked refresh, retain the accepted sections and overlay the refresh warning; never replace accepted data with an empty candidate.

### Warnings, source confidence, model lineage, and credits

Warnings use a severity hierarchy:

1. A full-width top warning with a 3px gold or red left rule for `Refresh pending`, `Refresh blocked`, `revision_pending`, or `blocked`.
2. A section-level gold warning row for `pre_draw`, `unresolved`, `insufficient_source`, `unsupported_topology`, or suppressed forecast data.
3. Quiet metadata for source confidence, freshness, release, and simulation details in the summary or disclosures.

Source confidence must be shown as a text value such as `High - official UEFA bundle` or `Reviewed fallback - operator-audited snapshot`, with the source bundle ID. Never communicate confidence by color alone. Model lineage must include model release ID, release manifest hash, model-data cutoff, feature cutoff, ruleset version/hash, projection run ID, simulation seed, simulation count, and the parent state/forecast references when those values exist.

Use two separate native `<details>` disclosures:

- `Source, model, and refresh lineage` - operational proof: batch ID, timestamps, source bundle/hash, confidence, release, ruleset, warnings, projection run, seed, count, and reason codes.
- `Data credits` - collapsed by default; source names, source URLs, license/attribution text, retrieval dates, and reviewed-fallback/operator notes.

The credits disclosure must not dominate the page and must remain discoverable by keyboard. Long URLs and hashes wrap or scroll inside the disclosure. Never call a data source live, current, or official unless the payload says so.

### Interaction and accessibility

- Use native controls, `<button>`, anchors, tables, and `<details>` where appropriate; no click-only `<div>` controls.
- Maintain visible focus outlines and keyboard access for route links, tabs, filters, clear action, disclosures, and row details.
- Announce filter result counts and state changes with a concise status region; do not reload the page.
- Keep warnings and accepted-snapshot identity visible while filtering or opening disclosures.
- Provide text equivalents for status marks, probability bars, and confidence colors.
- On narrow screens, tables scroll within their own panel and do not force page-wide horizontal scrolling except where an intentionally dense data table is the surface itself.
- Respect reduced-motion preferences; avoid animation as a status signal.
